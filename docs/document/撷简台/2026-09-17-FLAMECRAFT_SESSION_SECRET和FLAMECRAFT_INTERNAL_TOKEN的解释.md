# 2026-09-17-FLAMECRAFT_SESSION_SECRET和FLAMECRAFT_INTERNAL_TOKEN的解释.md

## 一、FLAMECRAFT_SESSION_SECRET —— Web 会话 cookie 的签名密钥

是什么：一把 HMAC-SHA256（HS256）对称密钥，只用于签名（不是加密）两类 cookie：

┌────────────────────────┬────────────────────────────────┬──────────────────────────────────────────────────────────────────────────────┬───────────────────────────────────────────┐  
│         Cookie         │              内容              │                                     作用                                     │                   代码                    │  
├────────────────────────┼────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────┼───────────────────────────────────────────┤  
│ flamecraft_session     │ 只有随机 sid（JWT 的 sub）     │ 让用户无法伪造/篡改别人的会话 id；IAM 令牌本身存服务端内存 store，不进浏览器 │ pkg/iamauth/session.go:49                 │  
├────────────────────────┼────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────┼───────────────────────────────────────────┤  
│ flamecraft_oauth_state │ 本次 OAuth 的 state + 回跳路径 │ 防 CSRF：回调时校验 URL 里的 state 与 cookie 是否一致                        │ session.go:127 签发 / session.go:162 校验 │  
└────────────────────────┴────────────────────────────────┴──────────────────────────────────────────────────────────────────────────────┴───────────────────────────────────────────┘

怎么生成：openssl rand -hex 32（产出 64 个十六进制字符 = 32 字节）。

硬性要求：FLAMECRAFT_AUTH_ENABLED=true 时必填且 ≥32 字节，否则启动直接失败（pkg/iamauth/config.go:198,206）。

影响：

- 必须固定不变：一旦更换，所有已签发的 cookie 验签失败 → 全员被强制重新登录。
- 多副本必须用同一个值：否则 A 副本签发的 cookie 在 B 副本验不过 → 用户随机掉线。
- 泄露 = 可伪造任意用户的 sid，等价于可冒用任意登录用户身份。所以必须放 Secret（k8s Secret），不入库、不入日志。
- 它不涉及 IAM：改它不影响公司 IAM 侧，只影响 FlameCraft 本地会话。

## 二、FLAMECRAFT_INTERNAL_TOKEN —— 服务端"自己调自己"的口令

是什么：内部自调用的共享令牌，通过请求头 X-Flamecraft-Internal-Token 传递，服务端用常时比较校验（pkg/iamauth/middleware.go:30,104-106）。

谁在用：AI 助手（pkg/aiagent）经 http.DefaultClient 调本机 API 时，由 LoopbackTransport 仅对回环地址自动注入该头（transport.go:31-34）；启动时由 pkg/flamecraft/parca.go:760 装好。

怎么生成：留空则启动时自动随机生成（randomHex(24) → 48 个 hex 字符）并写入进程环境（config.go:210-212）；生产建议显式设置并固定。

影响（重点）：

1. 多副本：各副本随机值不同 → 副本间互不信任。不过它只注入回环请求，实际跨副本用得少；显式固定更稳妥、也便于外部调用方使用。
2. ⚠️  内部令牌 ≠ 用户身份。它只证明"这是服务自己的调用"，不带任何用户身份。而出站身份已收敛为"必须用登录用户的 IAM 令牌"，所以经内部令牌进来的请求去访问 DrFile /  
制品库会失败（ErrNoUserIdentity）——它只对不需要用户身份的接口有意义。
3. ⚠️  MCP 目前是坏的（既有缺口，与本改造无关）：mcp-server/server.py 调 FlameCraft API 时不带任何认证头（只设 Content-Type），/mcp/\* 反代也不注入内部令牌 → 认证开启后 MCP 工具调用会被 401。若要让 MCP  
可用，就得让它带上这个令牌。
4. 变更该值不影响用户登录，只影响内部调用方。
