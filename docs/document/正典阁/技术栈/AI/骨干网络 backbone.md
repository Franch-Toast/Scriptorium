**一句话**：模型前半段负责「从原始数据提取通用特征」的主干部分——后面各任务头都吃它的输出；多任务共享同一骨干能摊薄计算、跨任务互补。

**是什么**：深度模型通常分两段：**backbone（骨干）**逐层把原始输入（图像、点云）变成越来越抽象的特征——浅层看边缘、纹理，深层看部件、结构语义；各层的空间化输出叫**特征图**（feature map）。**head（任务头）**在特征上做具体任务：分类、3D 框回归、车道线点集……骨干是共享底盘：任务越多，「一次骨干计算、多任务复用」的性价比越高——这也是多任务单模型方案的算力账核心。

**生活类比**：卡车底盘 + 不同上装：底盘（backbone）一次造好，装垃圾斗是垃圾车、装吊臂是吊车、装冷柜是冷藏车（不同任务头）。上装可以千变万化，底盘不必每车重造。

**在 C01 项目中的体现**：uni_model 内部有图像骨干与点云骨干两条提特征通路——graph_l2avp.cfg 中的 Filter 节点名 image_backbone / pp_backbone 就是按骨干输出的特征流命名分发的；点云骨干是 uni_model 第 0 路输入。骨干产出的 BEV 特征被全部任务头共享（见 [camera 子模块 1](../../../撰修司/E2E架构拆解/Perception/02_核心子模块拆解/子模块1：camera%20相机感知子模块.md)、[08 一帧生命周期：感知与规划](../../../撰修司/E2E架构拆解/08%20一帧生命周期：感知与规划数据流全景.md)）。
