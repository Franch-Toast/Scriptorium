# 阶段二：方案设计与验证

## 根因假设

（示例内容）内部统计模块每分钟向一个 `std::map` 注册采样条目，但仅在进程重启时清理，属于典型的**无界容器增长**。

<!-- more -->

## 修复方案

| 方案 | 思路 | 取舍 |
| --- | --- | --- |
| A | 引入 LRU 淘汰，上限 1 万条 | 改动小，行为可控 |
| B | 采样条目改为环形缓冲 | 吞吐更好，改动面大 |

选 **方案 A**，理由：改动局部化，风险最低，性能足够。

## 验证计划

- 压测 72 小时，观察驻留内存与 CPU 曲线是否平稳；
- 对比修复前后火焰图，确认统计模块不再出现平顶。
