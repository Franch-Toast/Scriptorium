## 一、背景与目标

此前开发中发现：**stg 环境 IAM 注册登录拿到的 token 无法访问 prod 的 drfile / adas_farm（制品库）等平台**（跨环境被拒 401）；而 **prod 环境注册登录的 token 可以访问**（同环境可用）。本测试的目标：让 FlameCraft **使用 prod 的 clientId/clientSecret + `https://drplatform-backend.deeproute.cn/drauth`** 在本地起服务、完成一次真实用户 SSO 登录，确认出站访问 **pipeline / DrFile(file-galaxy) / 制品库(prod-artifacts-server) / 下载链** 等核心接口是否能成功，并给出证据。

| `FLAMECRAFT_IAM_CLIENT_ID` | `flamecraft-oauth` |

| 登录用户 | `yifeizhang`（userId 6908） |

## 二、结论摘要（TL;DR）

1. **prod IAM 授权码流程在 FlameCraft 上完整打通**：`/auth/login` → drauth authorize → `iam.deeproute.cn` 登录 → 授权码回调 → prod clientSecret 换 token → 建立会话，`/auth/me` 返回 `yifeizhang / 6908`。
2. **SSO 授权码令牌（JWT，`aud=flamecraft-oauth`）在同环境（prod）内被资源服务接受**：file-galaxy listFiles = **200**（日志 `Use context accessToken: eyJraW…` = JWT 用户令牌）。
3. **8 项核心 API 中 7 项 2xx 成功**；唯一失败项 `namespaces/accessible` 是上游业务参数错误（file-galaxy 要求 `type` 非空），**不是鉴权问题**（对照实验：同请求带有效令牌=400 业务错、不带=401 未鉴权；`type:"READ"` 则 200）。
4. **制品库 prod-artifacts-server 接受 SSO 用户令牌**（`GetDriverPackageByTripName` 走用户令牌，`found=true`）。
5. **跨环境结论再次确认**：prod 令牌打 stg 资源服务被拒（对照项）。

### 3.3 脚本化 SSO 登录（关键链路）

无 SSO 会话时，`authorize` 302 到 `iam.deeproute.cn/#/signin?auth_request_id=…`。SPA 登录 API 为 `POST /drauth/auth/login`（`providerCode=deeproute-ldap` + `x-tenant-name`）。实测链路：

```
GET  /auth/login                       → 302 到 drauth authorize（带上 FlameCraft state cookie）
GET  authorize                         → 302 到 iam/#/signin?auth_request_id=X
POST /drauth/auth/login（LDAP 凭据）    → 200 返回 accessToken/refreshToken（expiresIn=604799s≈7天）
GET  iam/api/drauth/oauth/authorize?auth_request_id=X
       头: Authorization: Bearer <accessToken>   ← 关键：须带 Bearer，仅 cookie 会被弹回登录页
                                       → 302 到 flamecraft/auth/callback?code=…&state=…
GET  auth/callback（FlameCraft 用 prod clientSecret 换 code）→ 302 / 并下发 session cookie
GET  /auth/me                          → {"sub":"6908","name":"yifeizhang","email":"yifeizhang@deeproute.ai"}
```

> **发现**：drauth 完成 `auth_request_id` 需要把刚拿到的 access token 放在 **`Authorization: Bearer`** 头里；iam SPA 内部把 token 写进 `iam_access_token` cookie 再跳转，但**仅带 cookie 时服务端不认**（对照实验确认）。这里用的 token 是 LDAP 密码登录令牌（`aud=deeproute-ldap`，见 4.0），只用于让 drauth 认定"用户已登录"；**FlameCraft 出站用的是随后的授权码兑换令牌（`aud=flamecraft-oauth`）**，两者不同。登录脚本仅本次本地使用（`/tmp`，已清理），复现步骤见第七节。

## 四、测试结果

### 4.0 令牌对照（决定性证据）

授权码流程里实际存在**两种令牌**，需区分：

| 令牌 | 来源 | 声明 | 用途 |
|-|-|-|-|
| LDAP 登录令牌 | `POST /drauth/auth/login`（密码 grant） | `aud=deeproute-ldap` | 仅在 iam 登录页认证用户、完成 `auth_request_id`；**不作**出站凭证 |
| **SSO 授权码令牌** | `POST /drauth/oauth/token`（authorization_code，prod clientSecret） | **`iss=drauth`，`aud=flamecraft-oauth`，`client_id=flamecraft-oauth`，`scope=openid profile email`，`sub=6908`，7 天** | **FlameCraft 会话的出站凭证** |

**用 SSO 授权码令牌直接探测资源服务：**

| 目标 | HTTP | 结论 |
|-|-|-|
| prod file-galaxy `listFiles` | **200** | 同环境（prod→prod）接受 SSO 令牌 |
| prod artifacts `/packages/drivers`（不存在的包名） | 404 | 鉴权通过（否则 401 `user sub is empty`），仅查无此包 |
| stg file-galaxy `listFiles` | **401**`Token is invalid` | 跨环境（prod→stg）拒绝——环境隔离的又一实证 |

| 请求 | 结果 |
|-|-|

## 五、关键结论 / 待确认

1. **同环境可用结论在 prod 得到实证**：prod IAM 授权码流程签发的 **SSO 令牌（`aud=flamecraft-oauth`，`iss=drauth`）** 被 prod file-galaxy（200，FlameCraft 日志 `Use context accessToken: eyJraW…`）与 prod-artifacts-server（found=true）接受；同一令牌打 stg 资源 401。开发者此前 stg 令牌打 prod 资源 401 属**环境不一致**，与 aud 无关——aud 指向 OAuth 客户端并不妨碍同环境资源服务接受它。
2. `namespaces/accessible` 的 `type` 问题属 SDK/FlameCraft 缺陷（file-galaxy 要求 `type` 非空，SDK 发空串）。**已于 2026-09-16 修复**：`pkg/drfile/handler.go` 默认 `type=READ`（空值回落，`?type=WRITE` 仍可透传），新增单测 `TestAccessibleNamespacesTypeDefault`；实打 prod file-galaxy 验证默认 200（135 个 READ 空间）、WRITE 200（18 空间）。
3. 登录脚本与密码均不入库；测试用令牌 / cookie / jar 已清理；个人 DRPAT 与 SSO 令牌均为一次性，建议按需轮转。

## 七、复现速查

```bash
# 1) 本地域名映射 + HTTPS 反代（测后还原）
sudo sh -c 'echo "127.0.0.1 flamecraft.srv.deeproute.cn" >> /etc/hosts'
openssl req -x509 -newkey rsa:2048 -nodes -keyout /tmp/fc-tls/key.pem -out /tmp/fc-tls/cert.pem -days 1 \
  -subj "/CN=flamecraft.srv.deeproute.cn" -addext "subjectAltName=DNS:flamecraft.srv.deeproute.cn"
# nginx: listen 443 ssl, server_name flamecraft.srv.deeproute.cn, proxy_pass http://127.0.0.1:7070（独立 -c 配置）

# 2) 启动 FlameCraft（prod env，见 3.2）。SSO 登录核心步骤（可 curl 复现）：
#    a. curl -c jar https://flamecraft.srv.deeproute.cn/auth/login          → 302 到 drauth authorize
#    b. curl -b jar -c jar <authorize>                                      → 302 到 iam/#/signin?auth_request_id=X
#    c. curl -b jar -X POST https://drplatform-backend.deeproute.cn/drauth/auth/login \
#          -H 'Content-Type: application/json' -H 'x-tenant-name: deeproute' \
#          -d '{"providerCode":"deeproute-ldap","username":"<user>","password":"<pw>"}'   → 200 accessToken
#    d. curl -b jar -H "Authorization: Bearer <accessToken>" \
#          'https://iam.deeproute.cn/api/drauth/oauth/authorize?auth_request_id=X'  → 302 到 /auth/callback?code=...
#    e. curl -b jar -c jar <callback URL with -k>                           → 302 /，下发 session cookie

# 3) 带 session cookie 跑 API 矩阵（行程 YR-EC15S-17_20260912_030955）
#    GET  /api/drfile/pipeline/trip/driver-version?tripName=…   / trip/info …
#    POST /api/drfile/files/list  {"namespace":"trip","path":"/","page":0,"size":5}
#    GET  /api/drfile/driver/package-by-trip?tripName=…         / driver/info … / driver/download-url?tripName=…

# 4) 还原：停 FlameCraft / nginx，`sudo cp /tmp/fc-hosts.bak /etc/hosts` 或移除那行。
```

> 密码仅传入进程环境，不落盘、不入文档；登录脚本 `/tmp/fc-login.sh` 等为一次性产物，已清理。
