> **一句话导读**：这套文档只讲一件事——**一帧数据从传感器进来，到方向盘转动，中间发生了什么**。10 篇主干，从粗到细，不需要任何自动驾驶或算法背景。

## 这套文档适合谁

| 你是 | 建议 |
|-|-|
| 完全不懂端到端架构的新人 | 从 01 开始按顺序读，先建立画面，别急着看代码 |
| 有算法背景、想了解工程链路 | 直接读 02、03、09，再按需跳读 |
| 要改某段代码的开发者 | 先读对应篇章的「一句话结论」，再看篇末「证据与延伸」的文件位置 |
| 排障的人 | 直接看《10 概念地图与源码导读》§4 的「现象 → 位置索引」 |

## 三条阅读路线

### 路线一：15 分钟，建立画面

只读三篇，每篇 5 分钟：

1. **01 端到端是什么：看、想、动** —— 知道车上有哪三个角色、边界在哪。
2. **02 一帧全景：甘特图上的并行** —— 知道一帧 100ms 里谁先跑、谁等谁。
3. **03 数据流总览：topic 的一生** —— 知道数据从哪些 topic 进来、从哪些出去。

读完你应该能不看文档，在纸上画出「传感器 → 前处理 → 感知大模型 → 后处理 → 规划 → 控制 → 执行器」这条线，并说出每一段大概在干什么。

### 路线二：半天，完整理解

按 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10 顺序读完。建议节奏：

| 顺序 | 篇目 | 关注点 |
|-|-|-|
| 1 | 01 端到端是什么 | 三个角色、为什么解耦、单进程的含义 |
| 2 | 02 一帧全景 | 甘特图、触发链、并行度上限 |
| 3 | 03 数据流总览 | 输入输出 topic、数据形态的四次变化 |
| 4 | 04 前处理 | 帧同步、零拷贝、22 路模型输入 |
| 5 | 05 感知大模型 | BEV 为什么重要、一次推理多任务 |
| 6 | 06 后处理 | track_id、预测、融合、发布顺序 |
| 7 | 07 规划模型 | 参考线、DP/QP、任务链、fallback |
| 8 | 08 控制与执行 | 为什么被定位触发、横纵向控制、三道闸门 |
| 9 | 09 框架底座 | 组件/图/节点/流/topic 五概念 |
| 10 | 10 概念地图 | 当工具书用，不用通读 |

### 路线三：开发者，按需下钻

先读 03（数据流）和 09（框架），建立「topic 边界 + 组件内部图」的思维模型，然后：

- 改感知 → 04、05、06 的「证据与延伸」指向 `perception/` 与内层 cfg；
- 改规划 → 07 指向 `planning/`（任务链在 `em_planner.cpp`）；
- 改控制 → 08 指向 `control-by-wire/`；
- 改启动/装配 → 01、09 指向 `driver/config/dem/`、`driver/integration/mainboard.cc`、`platform/church/`。

## 这套文档是怎么写的

| 原则 | 具体做法 |
|-|-|
| 以数据流为纲 | 不按代码模块分册，按「数据从哪来、变成什么、到哪去」组织 |
| 先总后分 | 01~03 只讲粗粒度，04~08 才下钻；细节名词不提前出现 |
| 概念三层解释 | 每个术语先给一句白话，再给生活类比，最后给在本项目中的落点 |
| 结论先行 | 每个小节第一句就是结论，后面才是展开 |
| 证据可查 | 正文不堆代码，所有结论在篇末「证据与延伸」给出文件位置 |
| 图只表达一个观点 | 流程图不超过 12 个节点，时间关系用甘特图，清单用表格 |

## 关于准确性

本文档基于以下代码仓库当前状态整理：

- `/sandbox/driver`（C01 车型启动配置、组件配置、集成入口）
- `/sandbox/perception`（感知内层图与计算器）
- `/sandbox/planning`（规划任务链与子图）
- `/sandbox/platform/church`（框架：组件/图/topic/调度）
- `/sandbox/control-by-wire`（控制实现）

代码会演进，文档可能滞后。**遇到冲突时以代码为准**，并按篇末给出的文件位置自行核对。已经发现并修正的旧资料错误包括：模型输入路数（旧说法 50 路，实际 22 路）、在飞帧上限（旧说法 2，实际 1）、感知外层图名（旧说法 orin 图，实际 interleaving 图）、感知触发时机（控制是被定位触发，不是被轨迹触发）。

## 后续计划

本轮交付的是**主干篇**（01~10 + 本导读）。后续会在 `Perception/`、`Planning/` 子目录补充子模块级细节篇，例如：

- 感知：帧同步细节、相机/点云/雷达预处理、BEV 模型结构、跟踪与预测、融合与输出
- 规划：参考线生成、DP/QP 细节、速度规划、决策与场景、轨迹校验、泊车规划

细节篇会挂在对应主干篇目之后，读者可以按需深入，不必从头读。
