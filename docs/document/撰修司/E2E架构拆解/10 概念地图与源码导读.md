## 1. 三种查法

**一句话结论**：按词查（概念索引）、按流程查（源码地图）、按现象查（问题索引），三条路覆盖 90% 的日常需求。

| 你的问题 | 用哪张表 |
|-|-|
| 「这个词什么意思？」 | §2 概念索引表 |
| 「这个行为在哪个文件实现？」 | §3 源码地图 |
| 「我看到一个奇怪现象，从哪查起？」 | §4 现象 → 位置索引 |

使用建议：读正文时遇到生词，先在 §2 查「一句话解释」和「详解篇」，再跳过去精读；看完精读再回到本表，把一句话复述出来——能复述，才算真的懂了。

### 2.6 概念之间怎么串起来

上面的表是「点」，实际理解靠「线」。三句话把线串起来：

1. **时间线**：帧同步（`frame_nano_base`、`frame_id`）把异步传感器变成一帧一帧的输入，`kMaxFramesInFlight` 决定帧与帧之间是并行还是串行。
2. **数据线**：原始数据 → 张量（归一化/体素化）→ BEV 特征 → 多任务原始输出 → 跟踪与预测（`track_id`、预测轨迹）→ `/perception/objects`。
3. **决策线**：参考线 + Frenet（s/l）→ DP 粗选 → QP 精修 → 任务链合成 → 安全校验 → `/planner/trajectory` → 横/纵向控制（MPC/iLQR）→ `/control/control_command`。

框架层（组件/图/节点/流/topic）把这三条线装进一个进程：topic 负责跨组件，stream 负责组件内部。记住这个「三层线 + 一层容器」，就不容易在术语里迷路。

## 4. 现象 → 位置索引

| 现象 | 先去哪看 |
|-|-|
| 感知帧率不稳、偶尔跳帧 | 帧同步超时配置（`perception_graph_l2avp_interleaving.cfg` 的 `TIMEOUT`）、`kMaxFramesInFlight` |
| 规划用了旧地图做决策 | 感知发布顺序（`OUTPUT:0~4`）、规划触发 topic 是否是 `objects` |
| 控制不动或指令不生效 | 触发是否收到 `/localization/pose`、轨迹是否有值（`cache_size: 1` 是否被清空）、一致性检查是否报警 |
| 规划频繁超时 | `expected_proc_duration_ms: 500` 与实际耗时对比、任务链开关是否开了太多优化任务 |
| 障碍物 ID 频繁跳变 | 跟踪参数、遮挡场景、融合去重逻辑 |
| 端到端延迟变大 | 各组件 `expected_proc_duration_ms`、topic 队列长度、线程池配置、GPU 推理耗时 |

### 4.1 排障三步法

把现象索引用起来，建议固定成三步，避免一上来就乱翻代码：

| 步骤 | 问自己 | 去哪看 |
|-|-|-|
| 1. 数据到没到？ | 上游 topic 有没有、时间戳新不新 | 组件配置的 `input_channels`、topic 监控/告警 |
| 2. 处理跑了没？ | 组件被触发了吗、耗时超预算了吗 | `trigger_channels`、`expected_proc_duration_ms`、组件日志 |
| 3. 结果对不对？ | 输出内容是否合理（数值、数量、跳变） | 对应篇目的「证据与延伸」、debug topic |

三步分别对应「输入」、「调度」、「算法」。大部分线上问题在第一步和第二步就能定位，真正需要看算法细节的是少数。

> **一个实用习惯**：先把三个交接点（objects、trajectory、control_command）的「有没有、新不新、合不合理」确认一遍，就能判断问题落在哪个大段，再按本篇 §3 的源码地图缩小到目录。

## 5. 读完之后往哪走

本套主干 01~10 篇解决的是「脑子里有一张完整地图」。要继续深入，建议按下面三条路线：

| 路线 | 适合谁 | 怎么走 |
|-|-|-|
| 查漏补缺 | 刚入门 | 回到 01→02→03 重读，直到能不看文档画出粗粒度流程图 |
| 单模块深挖 | 要改感知/规划的人 | 以本篇 §3 的目录为入口，配合内层 cfg 逐个节点对照 |
| 排障实战 | 线上问题排查 | 用 §4 的现象索引定位环节，再回到对应篇目的「证据与延伸」找文件 |

> **后续规划**：本套是「主干篇」。后续会在 `Perception/`、`Planning/` 子目录补充子模块级细节篇（前处理细节、模型结构、跟踪预测、DP/QP、参考线、轨迹校验等），全部挂在对应主干篇目之下。

各路线的大致投入：路线一 15 分钟，路线二 3~4 小时（含对照代码查证），路线三按需投入。建议每读完一篇就合上文档，用自己的话回答三个问题：这一段的输入是什么、输出是什么、为什么需要它。能答上来再往下读，比一口气读完十篇效果好得多。
