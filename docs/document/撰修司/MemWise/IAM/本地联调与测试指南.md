# WeKnora × 公司 IAM（Drauth SSO）本地联调与测试指南

> 面向：想在本地把「仅 IAM 登录」这一期改动跑起来、并在浏览器里点一遍完整登录流程的人。
> 分支：`zyf/feat/IAM`。对应设计文档见 `website-docs/03-features/01-tenant-auth.md` 附录 A。

---

## 0. 一句话结论

本地要同时起 **3 个进程**：后端 `WeKnora-lite`（:8080）、前端 Vite（:5173）、HTTPS 反向代理（:443）。
浏览器**必须**用 `https://stg-memwise.srv.deeproute.cn` 打开——因为 IAM 侧注册的回调地址被锁死成
`https://stg-memwise.srv.deeproute.cn/api/v1/auth/oidc/callback`，用 IP / localhost / http / 带端口都会在回调时失败。

> **域名对照**：`stg-memwise.srv.deeproute.cn`（stg）与 `memwise.srv.deeproute.cn`（prod）是 WeKnora 前端/回
> 调域名；IAM（Drauth）后端另有一套地址（stg 为 `stg-drplatform-backend.deeproute.cn/drauth`，通过 `IAM_BASE_URL`
> 配置，见 §4）。**本地联调只用 stg 域名**（`stg-memwise.srv.deeproute.cn`）；生产部署时才把回调域名换成
> `memwise.srv.deeproute.cn`，并同步改 IAM 侧白名单与下面反代/证书/hosts 里的域名。

```
浏览器 https://stg-memwise.srv.deeproute.cn (443, 自签证书)
        │
        ▼
  HTTPS 反代 (Python, :443)
        ├── /api、/files ──► 后端 WeKnora-lite  (:8080)
        └── 其余         ──► 前端 Vite dev      (:5173)
```

## 1. 前置条件

| 项 | 说明 |
| --- | --- |
| 后端二进制 | `WeKnora-lite`（lite 单机版：SQLite + 内存队列）。缺失时 `SKIP_FRONTEND=1 make build-lite` 生成 |
| 前端依赖 | `frontend/node_modules` 已装（走公共 npm registry：`cd frontend && npm install`） |
| 环境变量文件 | `.env.lite`（含真实 stg 凭据，**不提交**）。见 §4 |
| SQLite 库 | `data/weknora.db`。首次需按 §5 补两列，否则 IAM 首登建号会失败 |
| 反代脚本与自签证书 | `https_proxy.py` + `wk.crt` / `wk.key`（CN=`stg-memwise.srv.deeproute.cn`）。见 §3 |
| hosts | 运行浏览器的机器上把 `stg-memwise.srv.deeproute.cn` 指到反代入口。见 §6 |
| 网络 | 后端能出网访问 `stg-drplatform-backend.deeproute.cn`（IAM 解析到内网 `10.3.8.141`，需 SSRF 白名单，见 §4） |

> IAM 侧已就绪（同事完成）：`memwise-oauth` 客户端、回调白名单 `https://stg-memwise.srv.deeproute.cn/api/v1/auth/oidc/callback`。
> 测过 `stg-drplatform-backend.deeproute.cn/drauth/oauth/authorize` 能 302 到 `stg-iam.deeproute.cn/#/signin`（无
> `redirect_uri mismatch`），即新回调能进 IAM 授权入口。
> 换个域名 / 端口测试，必须先让 IAM 管理员把新回调地址加进白名单，否则授权跳回会被拒。

## 2. 启动三个进程

在仓库根目录 `/sandbox/WeKnora` 执行。

### 2.1 后端 WeKnora-lite（:8080）

```bash
cd /sandbox/WeKnora
set -a && source .env.lite && set +a   # 载入 IAM 相关环境变量
./WeKnora-lite
```

看到监听 `:8080` 即成功。健康自检：

```bash
curl -s http://127.0.0.1:8080/api/v1/auth/oidc/config
# 期望：{"success":true,"enabled":true,"provider_display_name":"DeepRoute IAM","iam_only":true}
```

### 2.2 前端 Vite dev（:5173）

```bash
cd /sandbox/WeKnora/frontend
npm run dev            # 监听 0.0.0.0:5173
```

> 前端通过 Vite 代理把 `/api`、`/files` 转给 `http://localhost:8080`（见 `frontend/vite.config.ts`）。
> 但浏览器联调**不直接**连 5173，而是经反代 443（下一步），这样 origin 才是 https 域名。

### 2.3 HTTPS 反向代理（:443）

反代脚本 `https_proxy.py`（Python 标准库，无需第三方依赖）。作用：
- 让浏览器 origin = `https://stg-memwise.srv.deeproute.cn`，前端生成的 `redirect_uri` 才与 IAM 注册值一致；
- `/api`、`/files` → 后端 8080，其余 → 前端 5173；
- 转发到 Vite 时把 `Host` 改写成 `localhost:5173`，绕过 Vite 7 的 `allowedHosts` 校验；
- **原样透传 3xx**（不自动跟随重定向）——否则 `302 /#oidc_result` 会被跟到后端 catch-all 拿到 401，把成功误报成失败。

443 是特权端口，需 root：

```bash
sudo python3 /path/to/https_proxy.py
# 打印：HTTPS reverse proxy on :443 -> /api,/files=8080, else=5173
```

脚本内的 `CERT` / `KEY` 常量指向自签证书 `wk.crt` / `wk.key`；换机器时改成实际路径。脚本全文见 §8。

经反代自检（三条都要通）：

```bash
curl -sk https://stg-memwise.srv.deeproute.cn/api/v1/auth/oidc/config          # iam_only=true
curl -sk "https://stg-memwise.srv.deeproute.cn/api/v1/auth/oidc/url?redirect_uri=https://stg-memwise.srv.deeproute.cn/api/v1/auth/oidc/callback" | head -c 200   # 含 authorization_url 指向 stg drauth
curl -sk -o /dev/null -w '%{http_code}\n' https://stg-memwise.srv.deeproute.cn/  # 200 (Vite 首页)
```

## 3. 自签证书（若缺失需重建）

反代要一张 CN=`stg-memwise.srv.deeproute.cn` 的自签证书：

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout wk.key -out wk.crt \
  -subj "/CN=stg-memwise.srv.deeproute.cn" \
  -addext "subjectAltName=DNS:stg-memwise.srv.deeproute.cn"
```

浏览器首次访问会拦「不安全」。两选一：
- **省事**：点「高级 → 继续前往」，信任一次后同域回调也放行；
- **干净**：把 `wk.crt` 导入系统 / 浏览器信任库，避免每次点。

## 4. 环境变量（`.env.lite` 关键项）

`.env.lite` 含真实 stg 凭据，**不入库**。IAM 相关必填项：

| 变量 | 值 / 说明 |
| --- | --- |
| `DB_DRIVER` | `sqlite` |
| `DB_PATH` | `./data/weknora.db` |
| `STREAM_MANAGER_TYPE` | `memory`（lite 内存队列） |
| `OIDC_AUTH_ENABLE` | `true` |
| `AUTH_IAM_ONLY` | `true`（仅 IAM 登录：拒本地 login/register，前端自动跳转） |
| `IAM_BASE_URL` | `https://stg-drplatform-backend.deeproute.cn/drauth`（切 prod 只改这一处） |
| `OIDC_AUTH_ISSUER_URL` | 同上根地址 |
| `OIDC_AUTH_CLIENT_ID` | `memwise-oauth` |
| `OIDC_AUTH_CLIENT_SECRET` | 向 IAM 管理员申请（放 `.env.lite`，勿写进代码/文档/日志） |
| `OIDC_AUTH_SCOPES` | `"openid profile email"` |
| `OIDC_BIND_BY_SUBJECT` | `true`（按 `(issuer, subject)` 绑定，Drauth 无 email claim） |
| `OIDC_AUTH_SYNTHETIC_EMAIL_DOMAIN` | 合成占位邮箱域（如 `deeproute.ai`） |
| `OIDC_USER_INFO_MAPPING_USER_NAME` | `username`（Drauth userinfo 用户名字段） |
| `SSRF_WHITELIST` | `stg-drplatform-backend.deeproute.cn`（**必须**：IAM 解析内网，后端 SSRF 默认拦私网） |

> 授权 / token 端点会由 `IAM_BASE_URL` 自动派生为 `{base}/oauth/authorize`、`{base}/oauth/token`，无需单独配。

## 5. SQLite 快照补列（首次必做）

⚠️ 仓库既有问题（非本次改动）：`migrations/sqlite/000000_init.up.sql` 落后于 Postgres 版本化迁移，
缺 `tenants.api_principal_config`、`users.is_system_admin`。不补，IAM 首登自动建号会报
`failed to create workspace` / `failed to create user`。本地临时补列：

```bash
cd /sandbox/WeKnora
python3 - <<'PY'
import sqlite3
db = sqlite3.connect("data/weknora.db")
for sql in [
    "ALTER TABLE tenants ADD COLUMN api_principal_config TEXT DEFAULT NULL",
    "ALTER TABLE users ADD COLUMN is_system_admin NUMERIC DEFAULT 0",
]:
    try:
        db.execute(sql); print("OK  ", sql)
    except sqlite3.OperationalError as e:
        print("SKIP", sql, "->", e)   # duplicate column 说明已补过
db.commit(); db.close()
PY
```

> 根治方案（另开 PR）：补 SQLite 全量快照或新增 SQLite 迁移，与 Postgres 对齐。本次 `user_identities` 表已同时提供 Postgres（`000084`）与 SQLite（`000004`）迁移，不受此坑影响。

## 6. 浏览器所在机器的准备

浏览器几乎不在容器里，需让它能经域名连到反代 443。

**方式 A：SSH 端口转发（最稳）** — 在本地机器执行，保持不断开：

```bash
sudo ssh -L 443:localhost:443 <user>@<容器地址>
```
（本地绑 443 需特权；Windows 用管理员 PowerShell）

**方式 B：直连内网 IP** — 浏览器机器与容器同内网 / VPN 可达时，跳过转发，把域名指到容器 IP。

然后在**浏览器所在机器**的 hosts 加一行：

```
127.0.0.1 stg-memwise.srv.deeproute.cn      # 方式 A
# 或： <容器可达IP> stg-memwise.srv.deeproute.cn   # 方式 B
```
- macOS/Linux：`/etc/hosts`
- Windows：`C:\Windows\System32\drivers\etc\hosts`

## 7. 测试步骤与预期

### 7.1 浏览器手动走一遍

1. 打开 `https://stg-memwise.srv.deeproute.cn`（信任自签证书）。
2. **登录页无账号密码框**（IAM-only），自动跳转到 DeepRoute IAM 授权页。
3. 用公司账号登录并授权。
4. 跳回 WeKnora，自动建号 / 进入个人工作空间，右上角显示你的账号。

**验证点**：登录页无密码框；URL 跳到 `stg-drplatform-backend.deeproute.cn`；授权后落回 WeKnora 主界面且已登录。

### 7.2 后端 headless 验证（无浏览器，纯 curl）

用于快速回归、不依赖浏览器。密码登录拿 accessToken → 带 Bearer 调 `/oauth/authorize` 直接拿 302 code → 打 WeKnora 回调：

```bash
BASE=https://stg-drplatform-backend.deeproute.cn/drauth
# 1) 密码登录拿 accessToken（凭据放变量，勿硬写进脚本仓库）
ACCESS=$(curl -s "$BASE/auth/login" -H 'Content-Type: application/json' \
  -H "x-tenant-name: $OIDC_AUTH_TENANT_NAME" \
  -d "{\"username\":\"$IAM_USER\",\"password\":\"$IAM_PASS\"}" \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["body"]["accessToken"])')

# 2) 拿 WeKnora 授权 URL（含签名 state），提取 state
AUTH=$(curl -sk "https://stg-memwise.srv.deeproute.cn/api/v1/auth/oidc/url?redirect_uri=https://stg-memwise.srv.deeproute.cn/api/v1/auth/oidc/callback")
# 3) 带 Bearer 调 IAM authorize，302 里取 code；再打 WeKnora callback，期望 302 /#oidc_result=<base64>
```

期望：callback 返回 `302 Location: /#oidc_result=<base64(LoginResponse)>`；base64 解开是 `{success:true, user, memberships, token, ...}`；用其中 token 打 `/api/v1/auth/me` 返回用户/工作空间。二次登录幂等（`users` / `user_identities` 不新增行）。

### 7.3 IAM-only 门禁验证

```bash
curl -sk https://stg-memwise.srv.deeproute.cn/api/v1/auth/login \
  -H 'Content-Type: application/json' -d '{"email":"x@y.z","password":"whatever"}'
# 期望 403：Password login is disabled; sign in via IAM
```

### 7.4 单元测试

```bash
cd /sandbox/WeKnora
go test ./internal/application/service/ ./internal/application/repository/ \
  -run 'OIDC|Login|Identity|Token|UserInfo' -count=1
# 期望：ok
```

## 8. 反代脚本全文（`https_proxy.py`）

Python 标准库实现，无第三方依赖。放任意路径，改开头两个常量指向证书即可 `sudo python3 https_proxy.py` 运行。

```python
#!/usr/bin/env python3
"""本地 HTTPS 反向代理：让浏览器经 https://stg-memwise.srv.deeproute.cn(443)
访问本地应用，使前端生成的 redirect_uri 与 IAM 注册值一致。
  /api、/files  -> 后端 :8080
  其余          -> 前端 Vite :5173
转发到 Vite 时把 Host 改写为 localhost，绕过 Vite 7 的 allowedHosts 校验。
仅本地联调用。"""
import http.server, ssl, socket, urllib.request, urllib.error, sys

BACKEND = ("127.0.0.1", 8080)
FRONTEND = ("127.0.0.1", 5173)
CERT = "/path/to/wk.crt"   # 改成实际路径
KEY = "/path/to/wk.key"

HOP = {"connection", "keep-alive", "proxy-authenticate", "proxy-authorization",
       "te", "trailers", "transfer-encoding", "upgrade", "content-length", "host"}


class _NoRedirect(urllib.request.HTTPRedirectHandler):
    """反代必须原样透传 3xx，不能自己跟随——否则 302 /#oidc_result 会被
    urllib 跟到后端 catch-all(GET /)拿到 401，把成功登录误报成失败。"""
    def redirect_request(self, req, fp, code, msg, headers, newurl):
        return None


_opener = urllib.request.build_opener(_NoRedirect)


class Proxy(http.server.BaseHTTPRequestHandler):
    protocol_version = "HTTP/1.1"

    def _target(self):
        p = self.path
        if p.startswith("/api") or p.startswith("/files"):
            return BACKEND, "127.0.0.1:8080"
        return FRONTEND, "localhost:5173"  # 改写 Host 绕过 Vite 校验

    def _do(self):
        (host, port), hosthdr = self._target()
        body = None
        if "content-length" in {k.lower() for k in self.headers}:
            length = int(self.headers.get("Content-Length", 0))
            body = self.rfile.read(length) if length else None
        url = f"http://{host}:{port}{self.path}"
        req = urllib.request.Request(url, data=body, method=self.command)
        for k, v in self.headers.items():
            if k.lower() not in HOP:
                req.add_header(k, v)
        req.add_header("Host", hosthdr)
        # 让后端从 Host 推导出 https 回调地址
        req.add_header("X-Forwarded-Proto", "https")
        req.add_header("X-Forwarded-Host", "stg-memwise.srv.deeproute.cn")
        try:
            resp = _opener.open(req, timeout=30)
            self._relay(resp.status, resp.headers, resp.read())
        except urllib.error.HTTPError as e:
            # 3xx 也会走到这里(NoRedirect 后 urllib 把重定向当错误抛)，原样透传
            self._relay(e.code, e.headers, e.read())
        except Exception as e:
            self.send_error(502, f"proxy error: {e}")

    def _relay(self, status, headers, payload):
        self.send_response(status)
        for k, v in headers.items():
            if k.lower() not in HOP:
                self.send_header(k, v)
        self.send_header("Content-Length", str(len(payload)))
        self.end_headers()
        if self.command != "HEAD":
            self.wfile.write(payload)

    do_GET = do_POST = do_PUT = do_DELETE = do_PATCH = do_HEAD = _do

    def log_message(self, *a):
        pass


class Srv(http.server.ThreadingHTTPServer):
    daemon_threads = True
    address_family = socket.AF_INET


if __name__ == "__main__":
    ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
    ctx.load_cert_chain(CERT, KEY)
    srv = Srv(("0.0.0.0", 443), Proxy)
    srv.socket = ctx.wrap_socket(srv.socket, server_side=True)
    print("HTTPS reverse proxy on :443 -> /api,/files=8080, else=5173", flush=True)
    srv.serve_forever()
```

## 9. 常见问题

| 现象 | 原因 / 排查 |
| --- | --- |
| 授权后跳回报 `redirect_uri mismatch` | 浏览器没用 `https://stg-memwise.srv.deeproute.cn`（用了 IP/localhost/http/带端口）；或 IAM 白名单未登记该回调 |
| 回调 401 / 登录“失败”但后端日志显示成功 | 反代自动跟随了 302——确认用的是带 `_NoRedirect` 的脚本（§8） |
| `failed to create workspace` / `failed to create user` | SQLite 快照缺列，执行 §5 补列 |
| 后端报 SSRF / 无法连 IAM | `.env.lite` 缺 `SSRF_WHITELIST=stg-drplatform-backend.deeproute.cn` |
| Vite 返回 `Blocked request. Host not allowed` | 反代未改写 Host；或直接用域名访问了 5173（应走 443 反代） |
| 前端 502 | Vite（5173）没起或已挂，重启 `npm run dev` |
| `bind: permission denied` (443) | 443 是特权端口，反代需 `sudo` 运行 |
| token/userinfo 解析异常 | Drauth 用 `{body:{...}}` 信封 + camelCase 字段；代码已兼容（`user.go` 三处），勿回退 |

## 10. 关停

```bash
# 找到并关掉三个进程
pkill -f WeKnora-lite
pkill -f 'vite'            # 或在前端终端 Ctrl-C
sudo pkill -f https_proxy.py
```

> 这三个是本地临时进程，机器重启即消失，需按 §2 重新拉起。`data/weknora.db` 的补列（§5）持久，重启后仍在。
